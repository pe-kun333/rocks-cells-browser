# Grok Bot に「型の下書き」を頼む依頼文の見本（Phase 5b）

> 設計は `docs/plan-card-templates-grok-draft.md`（既定：Q17 = A1、Q18 = B1、Q19、Q21、Q25）。
> **アプリの動作は変えていません。** あなたがこの文を**自分で**コピーして Grok Bot に貼って送り、返ってきた JSON を型の窓の「読み込む…」で読ませるだけです（アプリから Grok へ自動で送ることはありません）。
> 見本の返答：`samples/grok-cardtpl-response-sample.json`（型の下書き）／`samples/grok-cardtpl-fill-sample.json`（穴埋めの値。型の窓の「読み込む…」か、空欄の小窓の「穴埋めファイルを読み込む…」で読めます）。

> **5c 以降**：型の窓の「Grok に頼む…」ボタンが、この A の文を自動で組み立ててコピーします（目的・今ある型の名前・選んだカードの文を選べます）。このファイルは、ボタンを使わず手で貼りたいとき・文面の見本として残しています。

## 使う前に知っておくこと

- 下の「依頼文」の **`【…】` の部分**を、自分の言葉に書き換えてから貼ります。要らない `【…】` の行は、行ごと消してください。
- **カードの本文は、あなたが選んだものだけ**を貼ります。何も選ばなければ、本文は入りません。貼る前に、**名前・連絡先・パスワード・社外秘が入っていないか**自分の目で見てください（Grok Bot に送られるのは、貼った文字だけです）。
- 返ってきた JSON は、読み込むと**確かめの小窓**が出て、あなたが「足す」を押して初めて保存されます。押さなければ何も変わりません。
- 型の `id` は、読み込むときに（重なると）つけ直されます。Grok が決めた `id` は何でもかまいません。

## A. 型の下書きを頼む文

次の枠の中を、まるごとコピーして使います。

````text
あなたは「カード（付箋のようなコメント）と、カードをつなぐ線の組み合わせ＝型」の下書きを作る手伝いをします。

【ほしい型の目的：ここに書く。例）読書会の準備に使う、5 枚くらいの型。本の要点と話したい問いを書き込める穴あきの型】

■ 型とは
- 型は、カード数枚と、カード同士の線（関連）をセットにした雛形です。あとで私がメモに貼って使います。
- 型には 3 つのモード（mode）があります。
  - "snapshot"（そのまま）：各カードの題と本文を、そのまま持つ。
  - "skeleton"（骨組み）：各カードの題（1 行）だけを持つ。本文は空にする（"body": ""）。
  - "hole"（穴あき）：本文に {{空欄名}} を書いておき、貼るときに私が値を入れる。空欄名は 1〜30 字で、波かっこ { } と改行を含めない。
- 1 枚の文は、題（1 行目）＋本文（2 行目以降）です。JSON では title と body に分け、body は先頭に "\n" を付けて書いてください（本文が無いなら ""）。

■ 線（links）の種類（kind）は、次の 6 つだけです
- "ground"（根拠）／ "counter"（反論）／ "next"（続き）／ "same"（同じ）／ "ask"（疑問）／ "supplement"（補足）
- { "from": "k1", "to": "k0", "kind": "ground" } は、k1 のカードから k0 のカードへ向けた線です（from = 線を持つ側）。
- 自分自身への線、同じ相手への 2 本目の線、cards にない key への線は書かない。1 枚から出す線は 10 本まで。

■ 上限と決まり
- 返す型は 1〜5 件。
- 1 つの型のカードは 2〜30 枚。
- 型の名前（name）は 40 字まで。【今ある型の名前：ここに書く。この名前とは重ねない。要らなければこの行ごと消す】
- 1 枚の文（題＋本文）は 2000 字まで。
- folder は "議論"・"調査"・"計画"・"その他" のどれか。
- tags は各カード 10 個まで（なくてもよい）。「宛て:」「送った:」「貼った:」で始まるタグは入れない（機械用のタグです）。
- dx・dy はカードを置く升目です。dx は 0・240・480（横 3 列）、dy は 0・150・300…（段）にする。
- 各カードの key は "k0"、"k1"… のように型の中で重ならないようにする。
- id は何でもかまいません（半角の英数字・- ・_ で 40 字まで。私のアプリで付け直します）。
- 材料に無い URL・人名・事実を作らない。

■ 材料（私が選んだものだけ。無ければこの節は無視してください）
【材料にするカードの文：ここに貼る。要らなければこの節ごと消す】

■ 返してほしい形式
JSON だけを返してください。説明の文を前後に付けない。コードの囲み（バッククォート 3 つの ```）で囲まない。補足は、いちばん外側の "note" に書く。形は次のとおりです。

{
  "format": "honeycomb-cardtpl",
  "version": 1,
  "templates": [
    {
      "version": 1,
      "id": "any-id-1",
      "name": "型の名前",
      "folder": "調査",
      "mode": "hole",
      "cards": [
        { "key": "k0", "title": "本", "body": "\n{{書名}}（{{著者}}）", "tags": ["調査"], "dx": 0, "dy": 0 },
        { "key": "k1", "title": "要点", "body": "\n{{要点}}", "tags": ["要点"], "dx": 240, "dy": 0 }
      ],
      "links": [
        { "from": "k1", "to": "k0", "kind": "ground" }
      ]
    }
  ]
}
````

> 枠の中の「例」は形の見本です。そのままの内容を返す必要はありません。

## B. 穴あきの型の「空欄を埋める」を頼む文

> 返ってきた値のファイル（`honeycomb-cardtpl-fill`）は、**空欄の小窓**（型の窓で穴あきの型を選んで貼るときに出る窓）の空欄に**先に入れる**だけです。入れても貼りません。内容を確かめて「貼る」を押したときだけ貼られます。読み込み方は、下の「B：穴埋めを頼む」の手順を見てください。

````text
あなたは、穴あきの「型」の空欄を、私が渡した材料から埋める手伝いをします。

【埋めたい型の名前：ここに書く。例）読書会の準備】
【その型の空欄名（{{ }} の中身）：ここに書く。例）書名・著者・要点・問い・進め方】

■ 材料（私が選んだものだけ）
【材料にするカードの文：ここに貼る。何も選ばなければ「材料なし」と書く】

■ 決まり
- 空欄名は、上に書いたものと一字一句同じにする。**知らない空欄名は書かない**。材料から分からない空欄は、値を書かずに省く。
- 値は文字だけ。1 つの値は 2000 字までに収め、長いときは短くまとめる。題の行に入る空欄は 1 行にする。
- 空欄は全部で 40 個までです。
- 材料に無い事実・URL・人名を作らない。

■ 返してほしい形式
JSON だけを返してください。説明の文を前後に付けない。コードの囲み（バッククォート 3 つの ```）で囲まない。補足は "note" に書く。形は次のとおりです。

{
  "format": "honeycomb-cardtpl-fill",
  "version": 1,
  "template": { "id": "（私が書いた id。分からなければ空でもよい）", "name": "読書会の準備" },
  "values": { "書名": "…", "著者": "…", "要点": "…" },
  "note": "どの材料を根拠に埋めたか"
}
````

## 試す手順（初心者向け）

### A：型の下書きを作ってもらう

1. この文書の「A」の枠をコピーします（枠の右上のコピーボタン、または選んで Ctrl+C）。
2. メモ帳などに貼り、`【…】` の部分を書き換えます（要らない行は消す）。カードの文を入れたいときだけ、`【材料にするカードの文】` に貼ります。
3. 書き換えた文を全部コピーして、Grok Bot の入力欄に貼って送ります。
4. 返事が **JSON だけ**で返ってきたら、それをコピーしてメモ帳に貼り、ファイル名 **`my-templates.json`**（文字コード UTF-8）で保存します。
   - 保存のとき「ファイルの種類」を「すべてのファイル」にして、`my-templates.json.txt` にならないよう気をつけます。
   - 返事に説明の文が混ざっていたら、`{` から最後の `}` までだけを残してください。
   - 練習したいときは、`samples\grok-cardtpl-response-sample.json` をそのまま使えます。
5. Honeycomb Browser（試しのフォルダの `Honeycomb Browser.bat` で起動したもの）で、下の区画の「**型を貼る ▾**」→「**型の窓を開く…**」（または `/` キー）を開きます。
6. 型の窓の「**読み込む…**」を押し、手順 4 のファイルを選びます。
7. **確かめの小窓**に、型の名前・フォルダ・モード・枚数が出ます。読めない型があれば理由も出ます。内容を見て、よければ「**足す**」を押します（押さなければ何も変わりません）。
8. 足した型は型の窓に並びます。型の窓でその型を選んで貼ると、カードと線が並びに入ります。気に入らなければ、貼ったあとは「元に戻す」、型は型の窓の「削除」（確認つき）で消せます。

### B：穴埋めを頼む

1. この文書の「B」の枠をコピーし、`【…】` を書き換えて Grok Bot に送ります。空欄名は、型の窓で穴あきの型を選んで貼るときの空欄の小窓に出ている名前を見て書きます。
2. 返ってきた JSON だけをメモ帳に貼り、`my-fill.json`（UTF-8）で保存します（`.json.txt` にならないよう注意。説明の文が混ざっていたら、`{` から最後の `}` までだけを残します）。練習なら `samples\grok-cardtpl-fill-sample.json` が使えます。
3. 次のどちらかで読み込みます。どちらも、読み込んだだけでは何も貼られません。
   - **型の窓の「読み込む…」**でそのファイルを選ぶ：ファイルの `template`（`id`、なければ `name`）の型を探して、空欄の小窓を**値が入った状態で開きます**。
   - **空欄の小窓の「穴埋めファイルを読み込む…」**：先に型の窓で穴あきの型を選び、空欄の小窓を開いてから押してファイルを選びます。今開いている型用のファイルだけ入ります（別の型用なら断ります）。
4. 小窓の空欄を見て、直したいところは直し、よければ「貼る」を押します（Esc でやめれば何も起きません）。型に無い空欄名の値は入りません。値が入らなかった空欄は、空のまま（`{{…}}` のまま貼ります）。
5. 読み込める形は `samples\grok-cardtpl-fill-sample.json` が見本です（`format` が `honeycomb-cardtpl-fill`・`version` が 1・`template` に型の `id` か `name`・`values` に空欄名→値。値は 40 個まで・1 つ 2000 字まで）。

### うまくいかないとき

| 見えたこと | 原因と直し方 |
|---|---|
| 「型のファイルとして読めません（JSON ではありません）」 | 返事に説明の文やコードの囲みが混ざっています。`{` から最後の `}` までだけを残して保存し直す |
| 「型のファイルではありません（format が …）」 | `"format": "honeycomb-cardtpl"` になっていません。穴埋め用のファイルは、型の窓の「読み込む…」で選べば自動で穴埋めとして扱われます |
| 「穴埋めのファイルではありません」 | `"format": "honeycomb-cardtpl-fill"` になっていません |
| 「…という型が見つかりません」 | `template` の `id`・`name` が、今ある型と合っていません。型の名前を直して送り直してもらう |
| 「穴あきの型ではありません」 | その型は穴あきではない（空欄がない）型です |
| 「入れられる値が 1 つもありません」 | 空欄名が型と違う・値が空です。依頼文に空欄名を書いて頼み直す |
| 確かめの小窓で「読めない型」と出る | カードが 0 枚・31 枚以上・名前がないなど。理由の文のとおりに Grok に直してもらう |
| 名前に「(2)」が付いた | 同じ名前の型がすでにあったためです（自動で付けます） |
